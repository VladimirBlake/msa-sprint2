# Стратегия миграции для Hotelio
## Первый этап
На первом этапе в рамках поставленной задачи был выделен функционал бронирования в отдельный микросервис. Теперь запросы к монолиту, связанные с созданием бронирования или получением списка бронирований отправляются с него на микросервис бронирований с использованием gRPC.

## Следующие этапы (To-Be)
Уже на этапе переноса первого микросервиса стоило рассмотреть создание API Gateway для маршрутизации запросов между монолитом и микросервисом, ибо текущие запросы на создание бронирований или их поиск по прежнему нагружают монолит, хоть и в меньшей степени.

На первом этапе микросервис бронирований совершает много вспомогательных запросов в монолит. Постепенно стоит выносить остальные модули монолита в отдельные микросервисы.

Можно подумать о внедрении GraphQL для агрегации данных из разных сервисов и стратегиях кэширования.
